\section{Lessons learned}\label{sec:lessons}

\begin{itemize}[leftmargin=*]
  \item \textbf{At $n=100$, evaluation details are as large as method effects.} The id-0 artifact, the evaluator library, the GT boxes, one misplaced test image and the train/test overlap each move AP by about FiDIP's published gain over fine-tuning (\cref{tab:sensitivity}). Building, testing and cross-checking the evaluator \emph{before} running experiments was the most valuable step of the project.
  \item \textbf{Verify the data, not just the code.} Hashing, near-duplicate search and label/image checks found six issues (\cref{tab:hygiene}). Each would have biased the results silently, and none shows up in a training curve.
  \item \textbf{Read the code, not only the paper.} Run literally, the README trains plain fine-tuning from random weights and selects on the test set. Once those were fixed, the training pipeline reproduced 93.6, but the domain-adaptation gain did not reappear.
  \item \textbf{Read published numbers diagnostically.} AP$_{50}$ = AP$_{75}$ = 98.5 alone shows that all headroom is at strict thresholds.
  \item \textbf{Cluster hygiene.} A slow \code{du} hung an SSH probe, the login node killed \code{unzip}, reading JPEG headers dropped the session, macOS \code{openrsync} could not talk to the cluster's rsync~3.2.5, and the lab share was unreadable. The fixes were \code{timeout} and BatchMode SSH, Slurm jobs even for light data work, tar over ssh, and our own checksummed download.
  \item \textbf{Guardrails need tests too.} The pre-registration gate parses \code{PREREGISTRATION.md}. When the selection evidence was once written as a table, three screening runs briefly became eligible; a post-commit check caught this before any evaluation. Configs are typed as well: \code{TRAIN.LAMBDA 0} (an int) failed, and \code{0.0} is required.
  \item \textbf{Agents get interrupted.} Workers stopped twice on usage limits, and parallel workers raced on one shared filesystem. Scheduled heartbeats, file-count checks and the live notebooks made recovery cheap, because nothing lived only in an agent's context.
\end{itemize}

\paragraph{Starting out.} I began by asking the agent for ``maximum points + bonus'', and within minutes I interrupted with ``Wait'' to switch to plan mode.
That pause shaped the project: the agent explored the cluster, the code and the data read-only, and I approved a written plan before anything changed.
I supplied the course slides and the STUDENT\_GUIDE, which the agent could not find on its own. They added deliverables mid-stream.

\paragraph{What the agent was good at.} It was strongest at work that is tedious by hand:
\begin{itemize}[leftmargin=*]
  \item reading unfamiliar code and spotting what decides a reproduction, such as random initialisation, $\lambda=0$ and test-set selection;
  \item auditing data files, which exposed the placeholder areas, the mislabelled file, the train/test copies and the id-0 artifact;
  \item running four streams in parallel, with tests and notes;
  \item checking citations.
\end{itemize}
Because checking was cheap, far more of the project went into evaluation conditions than I expected. That is how we learned that a stricter protocol reproduces 93.6 but not the domain-adaptation gain behind it.

\paragraph{Where I stepped in.} I forced planning before execution, provided the course material, approved the plan and the parallel setup, set policy (secrets handling, no AI co-author credit), and reviewed the results and this report.
The agent's mistakes surfaced through its own checks, not by luck. My takeaway is that an agent speeds up execution most when the human first fixes the goals, the rules and the standard of evidence.
